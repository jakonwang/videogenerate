# Web-Next 登录页设计稿对齐

## Summary

本轮仅调整 `apps/web-next` 的登录页面，不修改后端接口协议，不改动桌面端登录流程。

目标是将 `apps/web-next/app/login/page.tsx` 对齐用户提供的暗色登录页设计稿，保持前后端分离与组件化实现。

## 范围

- 页面：`/login`
- 前端项目：`apps/web-next`
- 不改动内容：
  - `services/api` 登录协议
  - 会话存储结构
  - 其他业务页面

## 设计对齐要求

- 深色背景下采用左价值主张、右登录卡的双栏布局
- 左侧保留品牌标识、访问标语、主标题、功能说明、三项价值点和底部入口链接
- 右侧保留单一登录卡片，包含手机号、验证码、显示名称、登录按钮、默认账号提示和错误提示
- 页面首屏比例贴近设计稿，避免桌面端首屏出现明显纵向溢出
- 主色高亮统一为紫蓝色系，卡片和输入框采用弱描边、轻阴影、深色表面层级

## 实现说明

- 使用 React 组件重写页面，不直接粘贴设计稿 HTML
- 保留既有登录逻辑：
  - `apiClient.login`
  - `setSessionToken`
  - `useSessionStore`
  - `next` 参数跳转
- 统一修复页面文案，移除乱码字符串
- 将品牌图形改为更接近设计稿的几何标识
- 收紧左侧标题字号、价值区间距、右侧卡片宽度与表单控件高度，使页面在 1600x980 桌面视口下更接近设计稿

## 使用说明

1. 启动 `web-next` 本地服务
2. 打开 `http://127.0.0.1:18280/login`
3. 使用默认测试账号登录：
   - 手机号：`13800138000`
   - 验证码：`123456`
   - 显示名称：任意非空

## 验证

- `npm run typecheck:web-next`
- `npm run build:web-next`
- 使用 Playwright 对 `http://127.0.0.1:18280/login` 进行桌面视口截图比对

## 平台兼容

- 开发测试环境：Windows
- 部署环境：Linux
- 本次改动未引入依赖 Windows 专属路径或系统能力的实现，保持跨平台兼容
