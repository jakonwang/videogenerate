# GMV Max AI 实时投放决策引擎现状差距分析

版本：V1.0

更新时间：2026-08-04

## 1. 结论摘要

当前系统已经具备 GMV Max 决策闭环的主体骨架，但还不是完整的实时投放决策引擎。

已具备的能力：

- TikTok GMV Max 日级数据同步和 30 天历史数据。
- 7 天趋势、生命周期、成熟状态和利润健康判断。
- ROI、预算利用率、利润底线和盈亏平衡 ROI。
- S1-S7 决策状态、优先级、推荐动作和阻断原因。
- 商品利润档案、AI Coach、三日观察计划。
- 实验、审批、执行、验证、结果回流和审计。
- 每 30 分钟运行一次的后台调度器。
- AI 不可用时的确定性规则回退。

主要缺口：

- 当前实时同步请求使用 `stat_time_day`，实时样本只是同一天的累计快照，没有小时或分钟维度。
- 当前实时样本没有保存累计值、增量值、账户本地时间、数据来源和新鲜度状态。
- 当前报告主要提供花费、GMV、ROI 和订单，未形成退款、拒签、取消、佣金和履约质量数据。
- 当前决策以日级聚合为主，还没有把流速、时段基准、边际 ROI 和订单质量合并成实时信号。
- 当前状态机有日级生命周期和成熟状态，但没有实时异常确认、恢复确认、滞回和冷却策略。
- 当前 AI Coach 读取历史摘要和利润边界，不是实时数据决策引擎的主判断器。
- 当前调度固定为 30 分钟，尚未按时段、账户时区和 TikTok API 限频动态调整。

## 4. 数据能力差距

### 4.0 六小时投放时段口径

实时决策按账户本地时区将每天划分为四个固定窗口：

| 时段 | 本地时间 |
| --- | --- |
| 时段 1 | 00:00-06:00 |
| 时段 2 | 06:00-12:00 |
| 时段 3 | 12:00-18:00 |
| 时段 4 | 18:00-24:00 |

采样和数据新鲜度检查仍可按 30 分钟执行；决策层按六小时窗口聚合累计值和增量值。每个窗口需要同时保存：

- 当前窗口累计花费、GMV 和订单。
- 当前窗口相邻样本的增量花费、增量 GMV 和增量订单。
- 当前窗口已经经过的分钟数和完成比例。
- 当前窗口与历史同一时段的中位数、P25 和 P75 基准。
- 当前窗口状态、置信度和数据完整度。

六小时窗口的作用是减少单点误判：窗口内的单次异常只进入观察，不直接切换阶段；只有连续采样持续偏离同一时段基准，才允许生成推荐动作。

### 4.1 当前可用字段

推广系列日级报告当前请求的核心指标为：

- `cost`。
- `gross_revenue`。
- `roi`。
- `orders`。

创意报表还包含：

- 展示、点击、CTR、CVR。
- 2 秒、6 秒和分段播放深度。
- CPA 和创意 ROI。
- 创意授权身份和视频编号，素材授权同步已覆盖推广系列身份列表。

利润模型已有：

- 采购、头程、尾程、仓储、平台佣金和达人佣金。
- 退货率和退货损失率配置。
- 贡献利润、盈亏平衡 ROI 和有效利润底线。

### 4.2 当前缺失字段

实时决策至少还需要：

- 样本采集时间戳。
- 账户本地日期和本地时间。
- API 返回的累计花费、累计 GMV 和累计订单。
- 相邻样本的花费、GMV 和订单增量。
- 样本窗口起止时间。
- 数据来源、请求 ID、数据新鲜度和兼容性状态。
- 时段基准花费、GMV、ROI、订单和 CPA。
- 退款、取消、拒签、履约完成和佣金数据。
- 订单质量置信度和利润模型完整度。

### 4.3 可复用接口和需要确认的接口

可直接复用：

- 现有 `gmv_max_report_get` 日级报告接口。
- 现有推广系列、商品、创意和身份同步接口。
- 现有 MCP 客户端的超时、能力发现和兼容性审计机制。

需要向 TikTok MCP 或 Apifox Hub 确认：

- 报告是否支持 `stat_time_hour`、`stat_time` 或其他分钟级维度。
- 是否存在推广系列实时概览接口。
- 是否存在订单、退款、取消、拒签、履约和佣金接口。
- 实时接口的查询窗口、分页限制、时区语义和调用频率限制。
- 累计指标是否可稳定用于相邻样本差分。

## 5. 决策规则差距

### 5.1 可复用规则

- 利润不完整时阻断平台写入。
- ROI 低于盈亏平衡线时进入利润保护。
- 单次 ROI 和预算变更受到变更预算限制。
- 实验和观察锁期间禁止重复变更。
- 数据过期、缺少连续证据和无模型时回退到规则证据。
- 推荐动作必须经过审批、执行、验证和结果回流。

### 5.2 需要新增的实时规则

- 当前时段预期花费比例与实际花费比例。
- 花费流速、GMV 流速和订单流速。
- 当前 ROI 与同店铺、同推广系列、同星期和同时间段基准的偏差。
- 当前边际 ROI，而不是只使用累计 ROI。
- 连续改善、连续衰退、单点异常和数据跳变识别。
- 订单质量不可用时禁止输出确定性利润结论。
- 低流量、低订单和低样本量时进入观察而不是立即调整。
- 特殊异常进入利润保护时仍保留审批和回滚条件。

## 6. 状态机差距

### 当前状态

- 决策状态：S1-S7。
- 生命周期：新品、成熟、衰退等日级阶段。
- 成熟状态：休眠恢复、诊断、速度受限、可放量、质量衰退等。
- 推荐状态：待审批、已批准、执行中、已执行、失败、过期。
- 实验状态：草稿、待审批、执行中、观察中、成功、失败、中性和回滚。

### 实时状态需要补充

建议增加独立的实时信号层，不直接替换旧阶段：

- `insufficient_data`：样本不足。
- `stale_data`：数据过期。
- `single_point_anomaly`：单点异常。
- `pace_normal`：节奏正常。
- `pace_under_delivery`：低于预期节奏。
- `pace_over_delivery`：高于预期节奏。
- `roi_decay`：连续 ROI 衰退。
- `quality_risk`：订单质量风险。
- `profit_protection`：利润保护。
- `observation_locked`：观察锁生效。

状态切换应明确：

- 最少连续样本数。
- 异常确认次数。
- 数据新鲜度上限。
- 观察锁和冷却时间。
- 恢复确认所需的连续健康样本。
- 允许进入审批的条件。
- 回滚触发条件。

## 7. 数据库差距

### 可继续复用

- `gmv_metrics`：日级历史数据。
- `gmv_realtime_samples`：实时快照基础表。
- `gmv_product_profiles`：商品历史档案。
- `gmv_decision_snapshots`：决策快照。
- `gmv_experiments`：实验和观察。
- `gmv_sop_interventions`：外部操作和验证。
- `gmv_audits`、`gmv_action_outcomes`：审计和结果回流。
- `gmv_coach_runs`：AI Coach 运行记录。

### 实时样本迁移方向

建议通过 `gmv_schema_migrations` 为 `gmv_realtime_samples` 增加：

- `sampled_at`。
- `local_date` 和 `local_time`。
- `window_start` 和 `window_end`。
- `cumulative_cost`、`cumulative_gmv`、`cumulative_orders`。
- `delta_cost`、`delta_gmv`、`delta_orders`。
- `data_source`、`request_id`、`freshness`。
- `raw` 中保留完整远程响应摘要。

是否新增订单质量实体取决于 TikTok 接口实际返回方式：

- 如果订单质量可按推广系列聚合，优先扩展 `gmv_realtime_samples` 和 `gmv_metrics` 的 payload。
- 如果需要订单明细或异步回流，应新增独立订单质量表，避免把明细塞进报表表。

## 8. 前端和操作流程差距

当前工作台可以展示：

- 日级 GMV、花费、ROI、预算利用率。
- 当前阶段、利润风险、AI 判断、三日计划。
- 推荐动作、审批状态、观察锁和审计记录。

实时决策需要新增：

- 当前时段进度和预期进度对比。
- 最近多个时间点的花费、GMV、ROI 和订单趋势。
- 累计值与增量值同时展示。
- 数据新鲜度、样本数量和订单质量可用性。
- 判断原因、影响、建议动作、阻断原因和预计观察周期。
- 动作前后数据、三日观察、回滚条件和结果评估入口。

操作闭环应固定为：

```text
发现问题 -> 查看连续证据 -> 查看利润边界 -> 生成推荐 -> 审批 -> 执行 -> 观察 -> 结果评估 -> 更新历史经验
```

## 9. 优先级和实施路线

### P0：实时基础和安全门禁

- 时序采样和样本差分。
- 按账户本地时区生成四个六小时窗口。
- 使用同一六小时窗口的历史基准进行比较。
- 实时状态信号。
- 数据新鲜度、样本充分性和异常确认。
- 决策证据和阻断原因。
- 复用现有审批、利润、实验锁和紧急停止。

验收标准：

- 能显示至少三个连续采样点。
- 能正确处理四个六小时窗口的跨日边界和账户时区。
- 窗口未完成时只显示进行中，不把未完成窗口与完整窗口直接比较。
- 能区分单点异常和连续异常。
- 数据过期时不生成可执行推荐。
- 所有动作仍进入审批、观察和审计链路。

### P1：订单质量、边际 ROI 和时段基准

- 接入或确认订单质量数据。
- 计算边际 ROI 和增量利润。
- 建立按账户时区的时段基准。
- 将实时信号接入现有决策快照。

验收标准：

- 订单质量不可用时显示不确定状态，而不是伪造利润判断。
- 调整建议同时展示累计 ROI 和边际 ROI。
- 时段基准跨日期可复用并能解释异常。

### P2：模型校准和高级自动化

- 使用实验结果校准阈值和预计收益。
- 跨商品、跨推广系列复用历史经验。
- 动态调度频率和 API 限频控制。
- 在既有审批保护下增加更精细的自动化策略。

验收标准：

- 每次自动化建议可以追溯到历史实验和结果。
- 预计收益展示置信度和估算状态。
- 自动化不会绕过平台写入保护。

## 11. 边界和风险

- 不把日级数据重复采样称为真正实时数据。
- 不在订单质量接口缺失时输出确定性净利润结论。
- 不因为预算未花完就自动增加预算。
- 不因为单个时间点 ROI 变化就切换阶段或执行动作。
- 不新增绕过审批的 TikTok MCP 写入路径。
- TikTok API 是否支持小时或分钟维度，需要在实施 Phase 1 前通过真实接口确认。
- 当前 AI Coach 的定位是结构化建议和规则增强，不能直接替代安全门禁。
- 现有素材授权同步修复独立于本分析，不与实时决策引擎混合发布。
