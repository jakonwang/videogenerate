# 2026-05-14 分镜图片生成性能优化

## 目标

- 缩短“批量分镜图片生成”阶段总体耗时。
- 只优化当前主链路，不改页面结构，不改后端协议。

## 问题结论

- 批量分镜图片阶段逐镜头执行。
- 每个镜头默认生成首帧和尾帧两张图，远端请求次数翻倍。
- 当前分镜图片阶段主消费结果是首帧，但批量入口仍默认生成尾帧。
- 相同参考图在多个镜头中会重复：
  - 转七牛公网 URL
  - 上传到 AtlasCloud

## 本轮修改

### 1. 批量分镜图片阶段只生成首帧

- 文件：`src/main/modules/clone/service.ts`
- `generateStoryboardGridsForProject(...)` 调用 `generateAllShotFrames(...)` 时显式使用：
  - `which: 'start'`
- `generateAllShotFrames(...)` 新增 `which` 参数，支持：
  - `start`
  - `end`
  - `both`

说明：

- 这样批量分镜图片阶段不再为每个镜头额外生成尾帧。
- 单镜头接口与其他链路仍保留 `both` 能力，不破坏兼容性。

### 2. 参考图转换与上传增加进程内缓存

- 文件：`src/main/modules/clone/qiniu.ts`
  - `toPublicUrlViaQiniu(...)` 增加缓存
- 文件：`src/main/modules/clone/atlasRetry.ts`
  - `uploadAtlasMedia(...)` 增加缓存

缓存键包含：

- 文件绝对路径
- 文件大小
- 文件修改时间
- 平台/用途信息

说明：

- 同一批参考图在同一次应用运行期间被多个镜头复用时，不再重复上传。
- 当文件内容变化时，缓存会因 `size + mtimeMs` 变化而失效。

### 3. 分镜图片参考图集合压缩

- 文件：`src/main/modules/clone/service.ts`
- 在 `generateGptShotFrames(...)` 中，分镜图片阶段不再把全部商品图、全部模特图、缩略图一股脑传给单次请求。
- 当前策略：
  - 首帧：
    - 商品参考图最多 3 张
    - 模特身份图最多 2 张
    - 合计最多 5 张，再附带缩略图时仍总量受控
  - 尾帧：
    - 起始首帧 1 张
    - 商品参考图最多 2 张
    - 模特身份图最多 1 张
    - 再附带缩略图，合计最多 5 张

说明：

- 这样可以降低图片编辑类接口的 multipart / 上传 / 预处理负担。
- 继续保持“商品参考图优先级最高”的产品一致性原则，不做 redesign。

## 使用说明

- 页面层无新增开关。
- 用户仍按原流程点击“生成分镜图片”即可。
- 当前优化主要作用于：
  - `/clone/[projectId]` 批量分镜图片生成阶段

## 验收标准

- 批量分镜图片生成时，不再默认为每个镜头额外生成尾帧。
- 同一次运行中，相同参考图跨镜头复用时不重复上传到七牛或 AtlasCloud。
- 单次分镜图片请求不再无上限携带大批参考图，而是使用压缩后的高优先级最小集。
- 分镜图片列表仍能正常展示每个镜头的首帧结果。
- Windows 开发和 Linux 部署保持兼容。
