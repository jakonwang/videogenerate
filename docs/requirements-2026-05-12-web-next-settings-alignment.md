# Web-Next 设置页设计稿对齐

## Summary

本轮仅调整 `apps/web-next` 的设置页面与其依赖的共享工作台壳层文案，不修改后端接口协议，不改动设置读写的本地存储方式。

目标是将 `apps/web-next/app/settings/page.tsx` 对齐用户提供的暗色设置页设计稿，并修复壳层中影响页面一致性的中文乱码。

## 范围

- 页面：`/settings`
- 共享壳层：`components/app/app-shell.tsx`
- 前端项目：`apps/web-next`
- 不改动内容：
  - `services/api` 协议
  - 登录鉴权协议
  - 设置保存介质，仍为浏览器本地存储

## 设计对齐要求

- 采用左侧导航、顶部总览卡、中部配置表单、右侧说明面板的桌面工作台结构
- 顶部总览需展示视频、图片、对话主链路和运行状态四个摘要块
- 左侧分类需改为高亮选中态的卡片式纵向导航
- 中部主表单需保持高密度、强信息层级和深色输入面板风格
- 右侧说明区需包含说明与边界、最近状态、配置指引入口
- 整页尽量贴近首屏工作台布局，减少不必要的纵向拉伸

## 已落实内容

- 重写设置页结构与中文文案
- 保留本地设置读写逻辑：
  - `readAppSettings`
  - `saveAppSettings`
- 将设置分类收敛为：
  - 视频模型
  - 图片模型
  - 对话模型
  - 通用设置
- 通用设置页内整合：
  - 工作台基础参数
  - 云存储配置
- API Key、Access Key、Secret Key 改为统一的深色密钥输入样式
- 顶部摘要区增加运行状态表达，保存后显示最近保存时间
- 修复 `AppShell` 内品牌、副标题、左侧导航、用户区等中文乱码，保证设置页整体风格统一

## 使用说明

1. 启动 `web-next` 本地服务
2. 打开 `http://127.0.0.1:18280/login?next=%2Fsettings`
3. 使用默认测试账号登录：
   - 手机号：`13800138000`
   - 验证码：`123456`
4. 进入设置页后可直接修改并点击“保存设置”
5. 设置仍保存到当前浏览器本地存储，不会下发到服务端

## 验证

- `npm run typecheck:web-next`
- `npm run build:web-next`
- 使用 Playwright 对 `http://127.0.0.1:18280/settings` 进行桌面视口截图比对
