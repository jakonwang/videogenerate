# 需求说明：`/models` 模特页设计稿对齐

## 背景

- 用户提供了暗色版模特页设计稿，要求将当前桌面端 `/models` 页面主体对齐设计稿。
- 明确约束：
  - 不修改左侧菜单栏
  - 不修改顶部栏
  - 仅调整 `/models` 页面内容区
  - 保持前后端分离与低耦合，复用现有数据与操作逻辑

## 本轮目标

- 将 `/models` 从旧的“左侧生成面板 + 中部列表 + 右侧详情”结构，收口为更接近设计稿的布局：
  - 顶部标题与操作按钮
  - 模特分类 tabs
  - 行内筛选与搜索
  - 高密度模特卡片网格
  - 右侧独立详情面板
- 保留原有模特创建、重命名、删除、绑定项目、打开封面等能力。

## 实现范围

### 修改文件

- `src/renderer/src/ui/views/ModelLibraryView.vue`

### 页面结构调整

- 标题区改为：
  - 左侧标题“模特库”与说明文案
  - 右侧“导入模特 / 创建模特”按钮
- 主内容区改为：
  - tabs 切换
  - 一行筛选器
  - 搜索框
  - 网格 / 列表视图切换
  - 四列卡片网格
- 右侧详情区改为：
  - 顶部模特卡摘要
  - 使用模特 / 编辑信息 / 更多操作
  - 基本信息
  - 标签
  - 简介
  - 作品预览

### 交互策略

- 不删除原有创建模特逻辑。
- 将原左侧生成面板收起为“创建模特”弹层，避免破坏首屏布局。
- 继续复用现有方法：
  - `refreshLibrary`
  - `refreshProjects`
  - `generateModel`
  - `renameModel`
  - `deleteModel`
  - `assignModelToProject`
  - `openCloneWithModel`

## 验收标准

- `/models` 主体视觉层级接近设计稿。
- 菜单栏和顶部栏保持不变。
- 模特卡片、筛选区、右侧详情区同时可用。
- 创建模特能力仍可通过弹层进入。
- 现有模特相关操作不丢失。
