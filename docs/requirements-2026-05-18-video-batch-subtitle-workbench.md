# 2026-05-18 视频批量加字幕插件工作台

## 功能目标

将 `视频批量加字幕` 插件升级为桌面端真实工作台，按设计稿完成以下闭环：

1. 选择素材
2. 配置字幕
3. 预览效果
4. 批量渲染

当前工作台已支持“手工时间轴字幕 + 静态标题贴片”双模式，不包含 ASR 语音转写能力。

## 页面结构

页面按桌面工作台结构组织：

- 顶部：标题、副标题、四步流程条、教程入口
- 左侧：本地上传 / 成片库选择、已选视频列表
- 中部：9:16 预览画布、视频预览、底部缩略条
- 右侧：字幕内容 / 样式设置
- 底部：任务队列、输出结果、GeeLark 推送入口

## 标题策略

支持两种固定策略：

- `单标题应用全部`
- `随机标题池`

规则：

- 标题支持多行输入
- 表情作为文本直接插入
- AI 生成标题进入标题池，不直接覆盖手工输入
- 随机标题池按视频索引选择候选，保证批量输出时每条视频可用不同标题

## 原视频保留规则

- 所有渲染输出均生成新的 mp4 文件
- 不覆盖本地上传源视频
- 不覆盖 clone 原成片 `finalOutputPath`
- 成片库来源视频仅作为引用输入

## GeeLark 衔接规则

- 成功输出的视频可以推入 GeeLark 发布可用池
- GeeLark 候选源新增 `batch_subtitle_output`
- 字幕增强版成片按独立输出记录管理
- 即使来源于 clone 成片，也不覆盖原成片发布状态

## 实现说明

- 主进程新增 `batchSubtitle` 模块，负责：
  - 素材信息补全
  - 任务持久化
  - AI 标题生成
  - ASS 字幕文件生成
  - FFmpeg 烧录输出
  - GeeLark 候选映射
- Web API 新增字幕插件私有接口：
  - `GET /plugins/video-batch-subtitle/jobs`
  - `POST /plugins/video-batch-subtitle/jobs`
  - `POST /plugins/video-batch-subtitle/jobs/:id`
  - `POST /plugins/video-batch-subtitle/jobs/:id/run`
  - `GET /plugins/video-batch-subtitle/outputs`
  - `POST /plugins/video-batch-subtitle/jobs/:id/push-to-geelark`
  - `POST /plugins/video-batch-subtitle/generate-titles`

## Windows / Linux 兼容说明

- 开发和测试以 Windows 为主
- 部署环境为 Linux
- 渲染与缩略图继续通过现有 ffmpeg 能力完成
- 路径拼接统一使用 Node 跨平台路径处理
- 字体优先使用可稳定命中的 `ttf/otf/ttc`

## 使用说明

1. 打开桌面端 `插件 -> 视频批量加字幕`
2. 添加本地视频，或从成片库选择已有成片
3. 配置标题策略、标题内容、字号、描边、阴影、位置和对齐
4. 中部预览确认效果
5. 点击“保存当前配置”
6. 点击“批量渲染”
7. 在输出结果区确认生成结果
8. 点击“进入 GeeLark 发布可用池”

## 验证方式

- `npm run typecheck`
- `npm run build`

人工验收重点：

- 页面结构是否贴近设计稿
- 本地上传与成片选择是否可用
- 标题与样式改动是否即时预览
- 批量输出是否生成新视频且保留原视频
- GeeLark 发布中心是否能识别字幕增强版输出

## 2026-05-18 补充：静态标题改为透明图叠加主链路

- 目标：为避免 Windows 开发与 Linux 部署环境下字体、emoji 与系统回退差异，静态标题默认不再依赖导出阶段文本渲染，而是先生成透明 PNG 图层，再与视频做 FFmpeg overlay 合成。
- 主链路：
  - `static_title` 模式默认使用 `titleRenderMode=overlay_image`
  - 预览通过后端生成真实透明图与预览短视频
  - 导出复用同一套标题位图参数生成独立 mp4
- 数据结构补充：
  - `titleRenderMode`
  - `titleItems`
  - `overlayImageConfig`
  - 输出项增加 `overlayImagePath`
- 兼容策略：
  - `timed_caption` 与 `hybrid` 现阶段继续保留原有 ASS 字幕链路
  - `capcut_mate` 保留为可选扩展，不作为静态标题默认主方案
- 使用说明：
  - 用户在“静态标题”模式下输入标题、emoji 或贴纸感文案后，预览区展示的就是实际透明图叠加效果
  - 批量渲染时每条视频会生成新的标题成片，不覆盖原视频
  - 成功输出后仍可继续推入 GeeLark 发布池
- 本次实现边界：
  - 优先解决静态标题预览与成片一致性
  - 不在本轮扩展逐词高亮、滚动字幕或完整贴纸素材管理系统

## 2026-05-18 补充：字体导入与备用字体库优先

- 目标：解决批量字幕标题在 Windows 开发环境与 Linux 部署环境之间字体不一致、预览和导出不一致的问题。
- 当前策略：
  - 字体下拉统一读取后端真实可用字体列表。
  - 字体来源优先级固定为：`用户导入字体 > 项目内置字体 > 系统字体兜底`。
  - 若用户要求两端完全一致，必须优先使用“项目内置”或“用户导入”字体，不依赖系统字体。
- 页面能力：
  - “样式设置”中新增“导入字体”入口，支持 `ttf / otf / ttc / woff2`。
  - 导入后立即刷新字体列表，并在可识别到新字体族名时自动切换到新字体。
  - 导入完成后立即重新触发真实预览，保证页面看到的效果就是导出效果。
  - 页面显示当前字体来源，明确区分“项目内置 / 用户导入 / 系统兜底”。
- 存储位置：
  - 用户导入字体统一存放在 `userData/videogenerate/fonts/`。
  - Windows 本地测试与 Linux 部署时，只要两端都加载同一份字体文件，即可保持一致。
- 兼容说明：
  - `ttf / otf / ttc` 为主推荐格式。
- `woff2` 允许导入，但部分 FFmpeg / libass 环境兼容性较差，只作为补充，不建议作为主方案。
- 项目已默认内置一批可直接打包分发的字体资源，当前至少包含：
  - 中文正文：`Noto Sans SC`
  - 中文手写：`LXGW WenKai`
  - emoji：`Noto Color Emoji`
  - 英文无衬线：`Nunito Sans`、`Open Sans`、`Roboto`
  - 英文装饰：`Pacifico`、`Playwrite IE`
- `npm run setup:fonts` 只负责补齐基础字体，不再删除仓库中已经存在的 `ttf / otf / ttc` 内置字体，保证额外内置字体可以长期保留并参与打包。
- 使用说明：
  1. 打开“插件 -> 视频批量加字幕”。
  2. 进入“样式设置”，先导入需要的字体文件。
  3. 在字体下拉中选择“用户导入”或“项目内置”字体。
  4. 确认真实预览效果后，再执行批量渲染。
  5. 若部署环境是 Linux，需要保证部署机也能加载同一份字体文件，避免回退到系统字体。
