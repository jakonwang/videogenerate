# DESIGN.md 重写说明（2026-05-05）

## 背景

原有 `DESIGN.md` 存在以下问题：

- 内容混杂旧规范与临时指令
- 存在乱码，影响阅读和执行
- 页面规范不完整，难以直接指导工程开发
- `/clone`、资源页、设置页缺少统一页面类型定义

## 目标

将 `DESIGN.md` 重写为项目唯一有效的页面设计规范，满足以下要求：

- UTF-8 正常可读
- 面向工程落地
- 明确布局、状态、颜色、排版、组件与交互规则
- 可直接作为后续页面重构与新页面开发基线

## 本次修改

文件：

- `DESIGN.md`

重写内容包括：

- 设计定位
- 全局交互原则
- 全局布局系统
- `/clone` Workflow 页面规范
- Resource / Settings 页面结构规范
- 颜色规范
- 字体与排版规范
- 间距与圆角规范
- 组件规范
- 文案规范
- 工程约束
- Codex 页面开发指令

## 关键规则

新的 `DESIGN.md` 明确规定：

- `/clone` 必须为三段结构
- 单步骤单主按钮
- AI 操作必须有状态机
- 核心区禁止整页滚动
- 所有页面使用统一 design token
- 页面优先保证流程和状态清晰，而不是视觉装饰

## 使用说明

后续所有涉及以下内容的修改，必须先参考新的 `DESIGN.md`：

- UI
- 页面布局
- 组件样式
- 交互结构
- 设计规范落地

如果用户只提出“高级”“精致”“好看”等抽象要求，默认按新的 `DESIGN.md` 解释和执行。
