# Web-Next 会员中心设计稿对齐

## Summary

本轮仅调整 `apps/web-next` 的会员中心页面，不修改后端套餐、订单、钱包和模拟支付协议。

目标是将 `apps/web-next/app/billing/page.tsx` 对齐用户提供的暗色会员中心设计稿，保持前后端分离和本地 Windows / 生产 Linux 兼容。

## 范围

- 页面：`/billing`
- 前端项目：`apps/web-next`
- 不改动内容：
  - `services/api` 套餐和订单协议
  - 模拟下单与支付接口
  - 用户、订阅、钱包数据结构

## 设计对齐要求

- 页面采用左主区、右辅助区的桌面工作台结构
- 左主区包含：
  - 页面标题
  - 当前套餐总览大卡
  - 套餐切换 tab
  - 套餐卡列表
  - 算力使用情况
- 右侧辅助区包含：
  - 会员权益
  - 最近订单
  - 账户摘要
- 全部文案统一为简体中文，移除损坏乱码
- 主卡片、按钮、信息层级和紫蓝高亮风格对齐设计稿

## 已落实内容

- 重写 `apps/web-next/app/billing/page.tsx`
- 保留既有逻辑：
  - `listPlans`
  - `listOrders`
  - `createOrder`
  - `payMockOrder`
- 当前套餐总览卡改为大尺寸深色信息卡
- 增加套餐选择 / 我的订单 / 使用统计切换
- 套餐卡重排为三列会员卡布局
- 右侧权益和订单区改成更接近设计稿的独立侧栏卡片
- 修复旧页面内套餐、状态、按钮、说明文案乱码

## 使用说明

1. 启动 `web-next` 本地服务
2. 打开 `http://127.0.0.1:18280/login?next=%2Fbilling`
3. 使用默认测试账号登录：
   - 手机号：`13800138000`
   - 验证码：`123456`
4. 登录后进入会员中心，可进行：
   - 查看当前套餐
   - 查看最近订单
   - 模拟创建订阅订单
   - 模拟创建算力包订单
   - 模拟支付待支付订单

## 验证

- `npm run typecheck:web-next`
- `npm run build:web-next`
- 使用 Playwright 对 `http://127.0.0.1:18280/billing` 进行桌面视口截图比对
