> 基于当前代码（`ui/unified-design-system` 分支，v5.0.129）的实际路由、导航、页面与模块整理。
> 日期：2026-11-15

## 〇、产品理念：把 TiktokCut 做成「AI 带货内容团队」

### 0.1 一句话定位

> **告诉它卖什么，它把内容做出来、发出去，并且越做越好。**

TiktokCut 不再是「一堆 AI 工具的集合」，而是**一个人就能带起来的带货内容团队**：AI 负责策划、生产、排期、复盘；人负责定目标、做选择、把关质量。

### 0.2 向标杆产品学什么

| 标杆产品 | 它强在哪里 | TiktokCut 借鉴成什么 |
|---|---|---|
| **Cursor / Claude Code** | AI 直接操作真实工具；先给计划、改动可审阅、人随时接管 | AI 调用系统内真实能力；**计划卡 → 审批 → 执行 → 产出可审阅**；任何一步可接管 |
| **Manus / 各类后台 Agent** | 交代完就能离开，后台跑，完成后交付结果 | 计划审批后**后台运行**，全局任务托盘看进度，完成后通知 + 进入审核收件箱 |
| **Linear / Raycast** | 极快、键盘优先、强主张、少即是多 | **一个输入框（Ctrl+K）既能搜索、跳转，也能对 AI 下指令**；默认流程有主张，不让用户做无谓选择 |
| **Shopify Sidekick** | AI 懂你店里的真实数据 | AI 读得到商品、素材、项目、发布表现，回答和计划都基于真实数据 |
| **Pippit（剪映电商）/ Creatify / HeyGen** | 贴一个商品链接就出视频 | **「贴链接 / 选商品 → 一套内容」** 作为最短路径 |
| **Canva / CapCut 模板** | 看效果选模板，一键套用 | **配方（Recipe）画廊**：每个配方带样片预览，选了就能跑 |
| **Tinder 式审核 / Superhuman** | 快速处理大量待决事项 | **审核收件箱**：AI 产出逐条「通过 / 重做 / 丢弃」，键盘快捷操作 |
| **ChatGPT 记忆 / Notion 知识库** | 越用越懂你 | **品牌记忆**：品牌调性、禁用词、常用模特、爆款脚本结构、你通过/否决的偏好 |
| **Notion / Figma** | 对象之间互相关联，一处可见全部 | **商品空间**：一个商品的选品数据、素材、项目、成片、发布、效果都在一页 |

### 0.3 六条产品原则

1. **目标驱动，而不是工具驱动**：用户说「这周给这款耳环做 20 条视频」，系统给出计划；而不是让用户自己在 10 个工具之间跳转。工具页面依然保留，供高手精细操作。
2. **以商品为中心**：所有内容都挂在商品下面；商品空间就是这款商品的「内容作战室」。
3. **AI 出方案，人做选择题**：AI 负责生成多个候选，人只需要挑选、通过或打回；打回的理由会进入品牌记忆。
4. **透明可控**：每次执行前都有计划卡（步骤、消耗、耗时）并**需要审批**；执行中可暂停、接管；产出可追溯来源。
5. **越用越好**：发布表现 + 审核偏好 → 品牌记忆 → 下一批计划自动更优。
6. **快**：一个输入框直达一切，拖进来就能用，后台跑不阻塞，打开即见上次进度。

### 0.4 北极星指标

| 指标 | 含义 |
|---|---|
| **商品 → 第一条可发布视频的时间** | 衡量「上手到产出」有多快 |
| **AI 产出采纳率** | 审核收件箱里「通过」的比例，衡量质量 |
| **每条可发布视频的成本** | 模型调用 + 账号额度折算 |
| **周活跃商品数** | 每周有内容产出的商品数量，衡量是否真正在用 |

## 二、串联问题（核心）

当前各模块基本是**孤岛**。从代码里所有 `router.push` 看，跨模块跳转只有「复刻 → 模特」「模特 → 复刻」两处。

```
现状：
选品 ──✗──> 商品库 ──✗──> 复刻 ──✗──> 发布
                          │
视频解析下载 ──✗──> 复刻参考视频
复刻成片 ──✗──> 素材库 / 字幕 / 水印 / Live Photo
首页「开始创作」──> 生产中心（旧流程，不是复刻）
首页统计 ──> 只统计生产任务，看不到复刻项目
```

具体断点：

1. **选品 → 商品**：爆品（StepWinners）结束只能回到选品列表，不能「一键建商品」。
2. **商品 → 复刻**：商品详情没有「用此商品做复刻」入口；复刻里绑定商品要反向去选。
3. **找参考 → 复刻**：视频解析下载拿到的视频不能直接「作为参考视频新建复刻」。
4. **复刻 → 后期 → 发布**：成片不会自动进素材库，也不能一键送去「字幕 / 水印 / 发布」。
5. **发布 → 数据**：发布后没有回流到 GMV MAX / 达人 / 数据看板的闭环。
6. **首页与主流程不一致**：首页主按钮、最近任务、今日数据都指向旧的「生产任务」，而导航主角是「复刻」。

## 三、排序与命名问题

### 3.1 排序
现状：首页 / 选品 / 模特 / 素材 / 商品 / 复刻 / 发布。
问题：「模特」「素材」是**资产**，被夹在业务流程中间；「商品」排在「素材」后面，但商品是复刻的前置。

### 3.2 命名
| 现名 | 问题 | 建议 |
|---|---|---|
| 复刻 | 保留名称 | 首页卡片补一句说明「照着爆款视频做完整成片」 |
| 生产 / 生产中心 | 与「复刻」概念重叠，`nav.products` 竟翻译为「生产」 | **批量混剪** |
| 素材 vs 商品图片素材 vs 素材库 | 三个「素材」 | 「素材库」统一；插件改名「视频拆图」 |
| 发布 vs TikTok 创意工作室 | 同一组件两个名字，用户分不清 | 发布拆为独立的 **发布中心**；创意工作室保留原名，提升为一级入口 |
| 插件市场 / 我的插件 | 插件实际都是内置功能，「安装」概念多余 | **工具箱**（按场景分组） |
| 动态照片生成器 | 正确但冗长，且藏在插件里 | **Live Photo**，提升为一级入口 |
| 身份定妆图 | 术语偏专业 | **模特定妆**（hover 解释） |

### 3.3 一致性问题
- `HomeView.vue` 全部硬编码中文，未走 i18n，切到英文/越南语时首页仍是中文。
- 插件 fallback 目录的 `status/enabled` 与实际可用不一致（如水印「未安装」却能直接进入）。
- 首页常用工具 8 个，插件中心 11 个，上架助手两处都没有。

## 四、V6 新版本方案

### 4.1 设计原则
1. **一条主线**：选品 → 商品 → 复刻 / 创意工作室 / Live Photo → 后期 → 发布 → 复盘，每一步都有「下一步」按钮。
2. **资产与流程分离**：流程放上面，资产（商品/模特/素材/模板）放「资产」分组。
3. **工具按场景分组**，不再有「安装」概念。
4. **首页 = 工作台**：展示「我进行中的项目」和「下一步该做什么」。
5. **AI 制片人贯穿全系统**：每个功能都是 AI 可调用的能力，人定目标、审批计划、挑选结果，AI 负责串联执行（见第〇、五章）。

### 4.2 三条生产线整合（复刻 / TikTok 创意工作室 / Live Photo）

> 原则：**名称不变、各自独立可用，同时能在彼此的流程里被「选用」**。不合并成一个工具，而是共用底座、互相打通。

#### 4.2.1 现状

| | 复刻 | TikTok 创意工作室 | Live Photo |
|---|---|---|---|
| 入口 | 主导航 | 插件（藏得深） | 插件（藏得深） |
| 输入 | 参考**视频** + 商品 + 模特 | 参考**图片** + 商品（或复刻分镜） | 参考**图片** + 商品（或复刻分镜） |
| 换商品 | 分镜图生成时锁定商品 | 借用 Live Photo 的换图服务 | 自有换图：区域 + 场景交互 + 验图 |
| 出视频 | 设置里的视频模型 API | **TikTok 官方创意账号池** | 设置里的视频模型 API + 运动模板 |
| 输出 | 多镜头**完整成片** | 单镜头 MP4（字幕、导出、发布 Tab） | Apple **Live Photo**（JPG+MOV） |

问题：
- 创意工作室、Live Photo 在后端已经支持「从复刻分镜创建」（`legacy_clone_shot` / `clone_shot`），但复刻页面里**没有入口**，用户不知道。
- 换图有 3 份实现（Live Photo、创意工作室借用、商品替换插件），提示词版本有 2 套。
- 发布功能藏在创意工作室里。

#### 4.2.2 定位：三条独立生产线 + 一个共用底座

```
              ┌──────────────┐   ┌──────────────────┐   ┌──────────────┐
  独立入口 →   │     复刻      │   │ TikTok 创意工作室  │   │  Live Photo  │
              │ 参考视频→成片  │   │ 参考图→换品→短视频 │   │ 参考图→换品→  │
              │              │   │（TikTok 账号出片） │   │  动态照片     │
              └──────┬───────┘   └────────┬─────────┘   └──────┬───────┘
                     │   可互相「选用」（见 4.2.3）               │
  ───────────────────┴────────── 共用底座 ───────────────────────┴──────────
   商品库（必选商品） · 商品换图服务（一套） · 提示词版本（一套，分换图/视频）
   素材库（输入来源 + 输出自动归档） · 后期队列（字幕/水印） · 发布中心 · 统一任务中心
```

- 三者都放进侧栏「创作」分组，**一级入口、名字不变**，不再藏在插件里。
- 每条线保留自己的项目列表和工作台，用户直接用哪一个都可以。
- 底座统一后，三者在「商品、素材、换图、提示词、后期、发布」上的体验一致。

#### 4.2.3 互相「选用」的连接点

| # | 在哪里 | 选用什么 | 效果 |
|---|---|---|---|
| X1 | 复刻 → 分镜设计 | 勾选分镜 →「送去创意工作室」「送去 Live Photo」 | 用复刻的分镜图（已锁定商品）直接建对应任务，带上项目、商品、脚本文案 |
| X2 | 复刻 → 分镜视频 | 每个镜头的**出片方式**：「模型 API（默认）」或「TikTok 创意工作室」 | 选创意工作室时由账号池出片，结果回填到该镜头，继续成片合成 |
| X3 | 复刻 → 成片合成 | 附加输出：「同时生成 Live Photo」 | 成片封面帧/指定镜头额外打包 Live Photo |
| X4 | 创意工作室 → 结果 | 「转成 Live Photo」 | 用已生成的 MP4 + 首帧直接走 Live Photo 打包，不必重新出视频 |
| X5 | Live Photo → 换图结果 | 「用创意工作室出视频」 | 把验图通过的换品图交给 TikTok 账号出片 |
| X6 | 创意工作室 / Live Photo → 新建 | 输入来源可选：上传 · 素材库 · **复刻项目分镜** · 视频拆图 | 选「复刻项目」时弹出项目 → 分镜多选 |
| X7 | 创意工作室 / Live Photo 结果 | 「作为复刻镜头素材」 | 可替换复刻中某个镜头的视频 |

所有跨线任务都**记录来源**（如「来自复刻项目 A · 镜头 3」），在双方页面上能互相跳转。

#### 4.2.4 共用底座要统一的部分

1. **商品换图服务**：以 Live Photo 现有实现（区域、场景交互、验图、重试）为准，复刻分镜、创意工作室、商品替换插件都调用它。商品替换插件保留，作为「只出图」的轻量工具。
2. **提示词版本**：两套合并成一套，按「换图 / 视频」和「适用线路」打标签。
3. **出片方式适配层**：「模型 API」与「TikTok 创意账号」做成两种出片引擎，复刻（X2）和 Live Photo（X5）都能选用；TikTok 账号池管理移到 **设置 → 账号与渠道**，创意工作室页面里保留快捷入口。
4. **输出归档**：三条线的结果都自动进素材库，按「商品 / 来源线路 / 项目」归档；商品详情新增「内容」Tab，汇总该商品在三条线的全部产出和使用/发布状态（复用 `listReusableCompletedItemsByProduct`、`markItemUsed`）。
5. **后期与发布**：字幕/水印统一走后期队列；创意工作室里的发布 Tab 拆成独立的「发布中心」，接收三条线的 MP4 输出（创意工作室页面仍提供「去发布」按钮）。

#### 4.2.5 首页的「开始创作」

首页主按钮改为三张卡片，对应三条独立线路：

| 卡片 | 一句话 | 需要准备 |
|---|---|---|
| 复刻 | 照着爆款视频做一条完整成片 | 参考视频 + 商品 (+ 模特) |
| TikTok 创意工作室 | 场景图换上你的商品，用 TikTok 账号批量出短视频 | 参考图 + 商品 + 创意账号 |
| Live Photo | 场景图换上你的商品，做成动态照片 | 参考图 + 商品 |

「继续上次」区域合并显示三条线的最近项目，标注线路类型。

#### 4.2.6 实施步骤

| 步 | 内容 | 风险 |
|---|---|---|
| M1 | 创意工作室、Live Photo 提升为侧栏一级入口（旧插件路由重定向）；首页三卡片 + 合并「继续上次」 | 低 |
| M2 | X1、X6：复刻分镜「送去…」与新建时「从复刻项目选分镜」（后端能力已有，只补前台） | 低 |
| M3 | X4、X5、X7：三线结果互转；跨线来源记录与互跳 | 中 |
| M4 | 出片方式适配层 + X2（复刻镜头可选 TikTok 创意工作室）+ X3；账号池移到设置 | 中 |
| M5 | 换图服务与提示词版本合并；输出自动归档 + 商品「内容」Tab；发布中心拆出 | 中 |

## 五、AI 中枢：AI 制片人

> 按第〇章的理念，AI 中枢的定位从「数字员工组织」调整为：**一个懂你商品和数据的 AI 制片人**。它能策划、调度系统里的所有功能、盯进度、交付候选结果；人审批计划、挑选结果。

### 5.1 定位调整（相对上一版）

| 上一版 | 调整后 | 原因 |
|---|---|---|
| 对用户展示 7 个「数字员工」 | **对用户只有一个 AI 制片人**；员工分工保留在后台做路由 | 概念越少越好用（Linear 式克制）；用户不关心谁在干活，只关心结果 |
| 6 个流程模板 | **3 个核心配方 + 2 个自动化**，配方带样片预览 | 先把最高频的场景做透 |
| 5 种入口并列 | **3 个主入口**：万能输入框、商品空间、审核收件箱；飞书和定时任务放后期 | 入口集中，用户形成习惯 |
| 写操作审批方式待定 | **每个计划都需审批**；发布 / 删除 / 投放调整在执行到那一步时再单独确认 | 已确认 |
| 大脑模型待定 | **沿用设置里的对话模型** | 已确认，零额外配置 |

### 5.2 现有基础

主进程已有 **Agent OS**（`src/main/modules/agent-os/`），preload 已暴露 `window.api.agentOs`，只是桌面端没有界面：

- 大脑 `brain.ts`：判断回答 / 追问 / 查询 / 发起流程。
- 规划器 `planner.ts`：拆成有依赖的步骤。
- 能力注册表 `capabilityRegistry.ts`：26 项能力已接真实服务。
- 运行控制 `service.ts`：计划版本、审批、暂停/恢复/取消、资源锁、自动修复。
- 飞书通道、命令目录文案（`locales → agentOs`）。

### 5.3 三个主入口

#### ① 万能输入框（Ctrl+K）—— 搜索、跳转、指令合一

- 输入「耳环」→ 搜到商品、项目、素材，回车直达。
- 输入「给耳环做 3 条复刻」→ 识别为指令，展开 **AI 制片人面板**（右侧抽屉）给出计划卡。
- 支持 @商品、@项目、@素材，支持拖入视频/图片。
- 计划卡内容：步骤列表、用到哪些功能、**预计消耗与耗时**、哪些步骤执行时还要再确认；按钮【执行】【修改】【存为配方】。
- 审批后**后台运行**，面板可关闭；顶栏任务托盘显示进度，完成后通知。

#### ② 商品空间 —— 以商品为中心的作战室

商品详情升级为「商品空间」，一页看全：

```
┌ 商品头部：图 · 名称 · 价格 · 库存 · 选品来源 ·【AI 做一套内容】【贴链接补资料】┐
├ 概览：内容数量 / 已发布 / 表现最好的视频 / AI 建议（下一步做什么）            ┤
├ 内容：复刻成片 · 创意工作室短视频 · Live Photo（按状态：生成中/待审核/可发布/已发布）┤
├ 素材：商品图、参考视频、场景图、视频拆图                                    ┤
├ 数据：发布表现、GMV MAX、达人寄样                                         ┤
└ 记忆：这个商品的卖点、禁用表达、适合的模特与脚本结构（AI 自动沉淀，可编辑）      ┘
```

#### ③ 审核收件箱 —— AI 出候选，人做选择题

- 所有 AI 产出（脚本变体、分镜图、成片、Live Photo、上架文案、发布排期）都进收件箱。
- 大预览 + 快捷键：`A` 通过、`R` 重做（可选理由：商品不像、动作怪、画面糊…）、`D` 丢弃、`←/→` 切换。
- 通过 → 自动入素材库并进入「可发布」；重做 → 带理由回到对应步骤；理由进入品牌记忆。
- 侧栏显示未读数，首页显示「待你审核 N 条」。

### 5.4 配方（Recipe）

配方 = 预先设计好的计划模板。配方画廊每张卡片带**样片预览、所需输入、预计消耗**。

| 配方 | 输入 | AI 串联的步骤 | 产出 |
|---|---|---|---|
| **一个商品，一套内容** | 商品（或贴商品链接） | 补全商品资料与分析 → 从素材库/爆款库挑参考 → 复刻 ×N → 分镜送 Live Photo → 字幕 → 进审核收件箱 → 通过后生成发布排期草案 | N 条成片 + M 个 Live Photo + 排期草案 |
| **跟拍一条爆款** | 爆款链接 + 1 个或多个商品 | 解析下载 → 复刻（一个参考 × 多个商品/模特）→ 字幕 → 审核 | 每个商品一条成片 |
| **场景图批量出片** | 一组场景图 + 商品 | 商品换图 → 创意工作室（TikTok 账号出片）或模型出片 → 可选转 Live Photo → 加水印 → 审核 | 每张图一条短视频 / Live Photo |

用户可以把一次满意的计划「存为配方」，配方可分享给团队（后期）。

**自动化**（后期，定时运行，产出进首页简报和收件箱，不自动执行写操作，只生成待审批计划）：

| 自动化 | 时间 | 做什么 |
|---|---|---|
| 每日简报 | 每天早上 | 失败任务、账号额度/模型余额、库存预警、待审核、今日待发布 → 首页简报 |
| 每周复盘 | 每周一 | 汇总发布表现 → 找出效果最好的脚本结构/模特/出片方式 → 生成下周内容计划（待审批） |

### 5.5 品牌记忆（越用越好）

| 记忆内容 | 来源 | 怎么用 |
|---|---|---|
| 品牌调性、禁用词、字幕风格、水印 | 用户在设置里填写 | 所有生成步骤自动带上 |
| 商品卖点、适合人群 | 商品分析 + 用户修改 | 脚本生成、上架文案 |
| 偏好 | 审核收件箱的通过/重做理由 | 规划时避开被否决的做法 |
| 爆款基因 | 发布表现 + 内容血缘 | 优先选用表现好的脚本结构、模特、出片方式 |

记忆对用户可见、可编辑、可删除（「AI 为什么这么做」可追溯到具体记忆）。

### 5.6 底座：统一对象、血缘与能力

1. **统一对象 ID**：`product:` `clone:` `creative:` `livephoto:` `asset:` `publish:` …，AI 和页面之间传递同一种引用。
2. **内容血缘**：每个产出记录来源、商品、模特、脚本、出片方式、提示词版本、消耗；4.2.3 的跨线连接自动写入。商品空间、审核收件箱、品牌记忆都读它。
3. **补齐能力**（在现有 26 项之外），按优先级：

| 优先 | 能力 | 说明 |
|---|---|---|
| P0 | `System.HealthCheck` | 模型可用性、余额、账号额度——计划卡估算和每日简报都依赖它 |
| P0 | `Asset.Search / Archive` | AI 找素材、归档产出 |
| P0 | `Clone.SendShots`、`LivePhoto.FromVideo`、`CreativeStudio.CreateFromImages` | 三条线互通（X1、X4、场景图配方） |
| P0 | `Review.Submit` | 产出送入审核收件箱 |
| P1 | `ProductResearch.PromoteWinner`、`Product.ImportFromLink` | 爆品转商品、贴链接建商品 |
| P1 | `Clone.ChooseVariant`、`Watermark.Apply` | 自动选脚本、批量水印 |
| P2 | `Publish.Schedule / Now`（危险）、`Insights.Read`、`GmvMax.Read / Suggest` | 发布与复盘闭环 |

### 5.7 安全与可控

| 规则 | 做法 |
|---|---|

### 8.2 有意保留的边界

- **发布**：AI 只生成发布草稿 / 排期，真正发布仍在发布中心由人确认。
- **重做**：收件箱的「重做」只记录原因进品牌记忆，不自动重新生成（避免未经审批的消耗），从「打开项目」手动重做。
- **效果数据**：发布渠道暂不提供播放 / 成交数据，复盘以审核通过率和发布成功为效果信号。
- **自动化**：简报 / 复盘只生成建议与「交给 AI」按钮，不自动创建或执行计划。
