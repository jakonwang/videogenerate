# GMV MAX 插件产品与界面分析任务

你是一名资深电商广告产品负责人、投放运营专家和桌面端 UX 设计师。

请先完整阅读 `GMV-MAX-产品与页面说明.md`，再逐张查看 `screenshots/` 中的 20 张截图。不要只根据文档标题给出通用建议，所有判断必须对应当前页面、当前功能和截图中的真实信息结构。

## 分析目标

请判断当前 GMV MAX 插件是否能让第一次使用的运营人员快速理解：

1. 今天先处理什么。
2. 为什么需要处理。
3. 点击哪里可以解决问题。
4. 操作会改变什么。
5. 哪些动作需要审批。
6. 操作后需要观察多久以及如何判断结果。

## 必须输出的内容

### 1. 执行摘要

- 用简明语言评价当前产品是否易学、易扫读、易操作。
- 列出最影响使用体验的五个问题，并按严重程度排序。

### 2. 用户任务与关键路径

- 定义新手运营、日常运营和管理审批者的主要任务。
- 画出从发现问题、查看证据、修复配置、提交审批、执行到结果回流的完整路径。
- 标出当前路径中的绕路、重复信息、断点和不可理解术语。

### 3. 信息架构

- 评价当前四组一级导航和十个二级页面是否符合用户心智。
- 给出新的导航结构，并明确每个页面的名称、职责和入口。
- 明确哪些页面应该保留、合并、拆分、移动或取消。
- 避免同时维护简洁模式和专业模式两套界面。

### 4. 十个页面逐页改版建议

对每个页面分别给出：

- 页面唯一目标。
- 用户进入页面后第一眼应该看到什么。
- 首屏保留的信息和主要按钮。
- 应移到详情、抽屉或折叠区的信息。
- 异常项目应如何同时表达原因、影响和处理动作。
- 推荐的布局结构，可使用文字线框图。
- 在 `1280x760` 下必须保持可见的内容。

### 5. 问题到处理动作的闭环

重点检查并重新设计以下路径：

- 利润或成本不完整，直接进入对应商品成本编辑。
- 素材疲劳或缺素材，直接进入素材处理和验证。
- ROI、预算或消耗异常，直接查看证据并生成待审批动作。
- AI 判断不可用，明确原因、设置入口和规则回退状态。
- 执行失败，直接查看失败原因、处理方式和重试条件。

### 6. 新手与专业用户兼容

- 默认界面应服务新手，但不能删除专业能力。
- 说明专业指标、历史数据、规则、回测和审计应放在哪里。
- 给出术语解释、风险提示和渐进披露方案。

### 7. 实施优先级

- 按 P0、P1、P2 划分改版工作。
- 对每项说明用户价值、改动范围、依赖和风险。
- 优先考虑复用现有数据、抽屉、审批和安全门禁，不建议无必要的后端重构。

### 8. 验收标准

给出可测试的验收标准，至少覆盖：

- 新用户能否在 30 秒内找到第一项待办及处理入口。
- 十个页面的标题、导航位置和主要动作是否明确。
- 问题是否均有原因、影响和处理按钮。
- 高级信息是否默认收起且可恢复查看。
- `1440x900` 和 `1280x760` 是否无横向溢出、遮挡和文字截断。
- 审批、利润保护、数据新鲜度、实验锁和紧急停止是否保持有效。

## 输出约束

- 使用中文。
- 先给结论，再给证据和方案。
- 引用具体页面名称和截图文件名。
- 不要建议制作营销首页。
- 不要使用纯视觉装饰掩盖信息架构问题。
- 不要删除现有审批、安全保护、审计和专业数据能力。
- 对无法从资料确认的内容明确标注“需要验证”，不要编造。
