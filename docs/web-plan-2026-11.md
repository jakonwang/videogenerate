# 网页版规划：让网页端拥有和软件一样的功能（最省资源方案）

> 日期：2026-11-17　基于分支 `ui/unified-design-system`（提交 `09f807ef`）的实际代码整理。

## 一、结论（先看这里）

**不新写一套网页版，把手机 App 直接做成网页版。**

- 手机 App（`apps/mobile`）本身就是 **Vite + Vue 的网页应用**，Capacitor 只是外壳：全仓库只用了 2 个原生插件（选品采集 `ProductResearch`、发布 `Publish`）和 2 个通用插件（本地存储、状态栏）。去掉外壳，它就能在浏览器里跑。
- 它已经覆盖了桌面端全部模块（四个阶段都已做完），而且全部走云端服务 `services/cloud`：生图 / 生视频、复刻分析与合成、字幕 / 水印 / 切片 / 混剪 / 链接解析、AI 制片人、审核、GMV MAX 与经营数据摘要。
- 所以网页版要做的只是：**① 加一个宽屏布局（像桌面软件那样有侧栏）② 替换 2 个原生插件 ③ 支持电脑上的拖拽上传和下载 ④ 作为静态文件部署**。不需要新服务器、不需要新后端、不需要新框架。

一套代码同时出「手机 App + 网页版」，以后加功能只写一次。

## 二、现状盘点

| 现有的网页相关部分 | 状态 | 处理建议 |
|---|---|---|
| `apps/web-next` 的 **账号 / 购买 / 设备 / 管理后台** 页面 | 在用，连 `services/cloud` | 保留，作为官网和账号中心 |
| `apps/web-next` 的 **旧工作台**（workspace、clone、materials、production、plugins…） | 连旧后端 `services/api`（把桌面模块直接搬到服务器上跑），主要功能停在 2026 年 5 月前 | 网页版上线后下线，少维护一套后端 |
| `apps/web`（Vite 旧版） | 2026-06 后无改动 | 删除 |
| `services/api`（旧网页后端，端口 18080） | 和 `services/cloud` 重复 | 随旧工作台一起下线，省一个常驻进程 |
| `services/cloud`（新云端，端口 18300） | 在用：账号、会员、同步、AI 网关、视频任务 | **网页版唯一后端** |
| `apps/mobile`（手机 App） | 四个阶段的模块都已有入口 | **网页版的代码来源** |

## 三、为什么这样最省资源

| 方案 | 前端工作量 | 后端 | 服务器开销 | 以后维护 |
|---|---|---|---|---|
| **A. 手机 App 网页化（推荐）** | 加宽屏布局 + 2 个插件替换 | 复用 `services/cloud`，零新增 | 只多一份静态文件（可放 CDN） | 一套代码 |
| B. 继续做 `web-next` 旧工作台 | 大量页面要补，且要改连新后端 | 要么维护 `services/api`，要么重接 | 多一个常驻 Node 进程 + 服务器本地处理 | 三套界面（桌面 / 手机 / 网页） |
| C. 把桌面端界面整体搬上网页 | 桌面界面依赖 Electron 本地能力（本地文件、ffmpeg、账号 Cookie），改造量最大 | 要新写一整套服务端 | 最高 | 最难 |

## 四、功能对照：每个模块在网页上怎么实现、花多少资源

「谁出力」决定成本：**模型厂商出力**的，服务器只排队和查询状态，几乎不耗资源；**服务器 ffmpeg 出力**的要限流；**电脑代跑**的服务器零成本。

| 桌面模块 | 网页实现 | 谁出力 | 服务器资源 |
|---|---|---|---|
| 工作台 / AI 制片人 | 手机版 AI 制片人（计划卡、审批） | 对话模型 | 很低（只花 tokens） |
| 审核收件箱 | 手机版审核页 | — | 很低 |
| 复刻 | 云端分析 + 模型出分镜图 / 分镜视频 + 云端合成 | 模型厂商 + 合成时服务器 ffmpeg | 中（合成一次几十秒 CPU） |
| 图生视频 | 云端生视频任务 | 模型厂商 | 很低 |
| 商品替换 / 品牌水印 / 图生图 / 上架助手 | 云端生图 + 对话模型 | 模型厂商 | 很低 |
| 视频解析下载 | TikHub 接口 | 第三方接口（按次计费） | 很低 |
| 视频字幕 | 云端转写接口 + ffmpeg 烧字幕 | 转写接口 + 服务器 | 中 |
| 视频水印 | 云端 ffmpeg | 服务器 | 中（预览在浏览器里用画布做，不占服务器） |
| 直播切片 | 云端切片（尽量不重新编码） | 服务器 | 低 |
| 批量混剪 | 云端混剪任务 | 服务器 | **高**（要限量） |
| 商品 / 模特 / 素材 / 模板库 | 同步记录 + 文件 | 存储 | 按空间（已有每人 2 GB 配额） |
| 选品 | 飞瓜数据 + 选品记录；手机采集在网页上不可用 | — | 很低 |
| 发布中心 | 下载成片 + 一键复制标题和话题；手机上仍可直接分享到 TikTok | — | 零 |
| tk创意室 | 需要 TikTok 创意账号 Cookie，不放服务器：**网页下单，电脑代跑**（和 GMV MAX 同样的桥接方式） | 用户电脑 | 零 |
| GMV MAX / 达人管理 / 店小秘 / 数据复盘 | 电脑同步上来的摘要 + 网页做决定、电脑执行（手机版已是这样） | 用户电脑 | 零 |
| 设置 / 会员 | 模型密钥统一在管理后台；会员沿用现有页面 | — | 零 |

## 五、生成视频怎么做到最省资源

1. **重活交给模型厂商**：图生视频、分镜视频、生图都是调用厂商接口，服务器只负责排队（已有并发上限 `CLOUD_AI_JOB_CONCURRENCY`，默认 4）、查进度、存结果。不需要 GPU 服务器。
2. **服务器只做必须的 ffmpeg**：合成、烧字幕、水印、混剪。做法：
   - 单独一条 ffmpeg 队列，并发 1～2（按服务器核数）；
   - 每人每天的处理分钟数设上限，会员档位决定额度；
   - 切片、拼接优先「不重新编码」（直接复制视频流），速度快几十倍；
   - 必须编码时用较快的预设，输出控制在 1080p 以内。
3. **浏览器能做的不上服务器**：水印位置预览、裁剪框、封面选择用画布在浏览器里完成，只把最终参数交给服务器。暂不引入 ffmpeg.wasm（约 30 MB，在普通电脑上很慢）。
4. **存储有期限**：生成结果默认保留 30 天，用户「存入素材库」的才长期保留；临时上传的参考视频合成后 7 天删除。现在已有每人 2 GB 配额和 200 MB 单文件上限，需要补自动清理。
5. **空间不够时再上对象存储**：先用服务器磁盘；用户量上来后接七牛（桌面端已有七牛设置），浏览器直传、服务器只发签名，不经过服务器带宽。
6. **防止被刷**：沿用现有每分钟 / 每天 AI 调用上限（`CLOUD_AI_PER_MINUTE`、`CLOUD_AI_PER_DAY`，默认每天 500 次），会员过期即停。

## 六、分期（每期结束都能直接用）

### W1 手机 App 变网页版（约 3～5 天）
- `apps/mobile` 增加网页构建目标，部署到 `https://你的域名/app`（和云端同域，免跨域）。
- 宽屏布局：屏幕 ≥ 1024px 时显示和桌面一样的左侧导航，内容区多列；窄屏保持手机样式。沿用 `themes.css`，外观与桌面一致。
- 替换原生插件：发布 → 浏览器下载 / 系统分享；选品采集 → 网页隐藏该入口；本地存储在网页上自动用浏览器存储。
- 电脑交互：拖拽上传、多选文件、结果下载。
- 验收：在浏览器里登录后，能走通 商品 → 复刻成片、图生视频、字幕 / 水印 / 切片，以及 GMV 摘要查看。

**W1 进度（2026-11-17 已完成）**
- 构建：`apps/mobile` 里 `npm run build:web`，产物在 `apps/mobile/dist-web`；本地预览 `npm run dev:web`（端口 18291，`/api` 自动转到本机云端 18300）。
- 部署：云端服务直接在 `/app/` 提供网页版（`services/cloud/src/webApp.ts`，目录可用 `CLOUD_WEB_APP_DIR` 指定），和接口同域，不需要另开服务器或配置跨域。生产环境只需在部署时多跑一次 `npm run build:web`。
- 登录：网页版以「网页会话」登录，不占手机或电脑的设备名额，不会把用户的手机顶下线；会员校验照常。
- 宽屏：≥1024px 显示桌面式左侧导航（按 创作 / 资产 / 经营 分组），内容居中，素材网格自动加列，弹层改为居中对话框；手机版式不变。
- 发布：网页上「下载」代替「存到相册」；TikTok / 抖音按钮会下载视频、复制描述并打开对应的网页上传页；「分享 / 下载」在支持的浏览器里调用系统分享。
- 上传：所有选择文件的地方都支持把文件直接拖进来。
- 选品的手机采集在网页上隐藏（需要操作手机上的抖音）。
- 测试：`npm run test:cloud-web-app`；在浏览器里验证了登录、同步、作品库下载、拖拽上传、水印工具、发布中心，以及手机宽度下版式不变。
