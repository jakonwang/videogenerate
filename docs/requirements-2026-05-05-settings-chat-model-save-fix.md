# 设置中心脚本模型保存修复

## 摘要

修复设置中心“对话模型 / 脚本模型”无法保存更新的问题。

## 问题原因

- 对话模型输入框使用统一绑定，但读取逻辑错误：
  - 只要 `apifoxHub.chatModel` 曾经有值，就会优先显示它
  - 即使当前供应商已经切换为 `GRS.AI`
- 导致现象：
  - 用户修改脚本模型后点击保存
  - 保存实际成功，但界面回读仍显示旧值
  - 用户感知为“无法保存更新”

## 修复内容

- 对话模型读取逻辑改为严格按当前供应商决定：
  - `ai666` 时读取 `apifoxHub.chatModel`
  - `GRS.AI` 时读取 `grsaiAnalysisModel`
- 对话模型写入逻辑也改为严格按当前供应商写入
- 常用模型快捷按钮同样按当前供应商写入对应字段
- 新增独立字段 `chatProviderPrimary`
  - 脚本/对话供应商不再复用 `apifoxHub.enabled`
  - 即使视频或图片仍在使用 `ai666`，脚本供应商也可以单独切换为 `GRS.AI`
- `/clone` 脚本分析链路改为按 `chatProviderPrimary` 选择 ai666 或 GRS.AI

## 验收

1. 切换到 `ai666` 后修改脚本模型，保存后回读一致
2. 切换到 `GRS.AI` 后修改脚本模型，保存后回读一致
3. 切换供应商后不会再被旧供应商字段回显覆盖
4. `npm run typecheck` 通过
