# SKU（款号）关联设计

状态：待确认，未开始开发。日期：2026-11-24

## 一句话

一个款式一个**款号**（如 A-152），以商品库为款号档案；选品、直播测试、店铺商品、销售库存、广告都靠款号自动对上，
用户只需要填一次款号。

## 现状（本机真实数据，2 家店）

| 检查 | 结果 | 结论 |
|---|---|---|
| 店铺商品 956 个，标题结尾带款号 | 782 个（82%） | 按标题匹配可行 |
| 商品卡片数据（浏览/点击/成交）能对上款号 | 10631 / 11522 行（92%） | 可以直接按款号汇总 |
| 订单行有商家 SKU | 4692 / 4942（95%） | 销量可以按款号汇总 |
| 同一款号在两家店都有 | 363 个 / 533 个款号 | 款号是唯一能跨店合并的键 |
| 标题款号与商家 SKU 不一致 | 14 个 SKU（如标题 A-257、SKU A-275） | 多半是填错，要列出来让人改 |
| 没有任何款号的商品 | 142 个，其中有「直播间选款」这类通用链接 | 不能硬猜，单独列出 |
| 规格编号 59、0、1 和长数字 | 重复或无意义 | 不能当款号 |
| 商品库 26 个，名称本身就是款号 | 14 个，其中 11 个能在店铺对上 | 可一键迁移 |
| 商品库有款号字段 / 已手工绑定店铺商品 | 没有字段 / 2 个 | 要新增 |
| 单个商品的直播场次数据 | 目前没有同步，只有店铺级直播 GMV | 阶段 3 需先验证商家后台接口 |

## 规则

### 款号格式
- 存储前统一：去首尾空格、转大写、全角转半角、连续空格合并。`a-152`、`Ａ－152` → `A-152`。
- 允许字母、数字和符号（- _ . /），如 A-152、AA-3、A-4-1。最长 80 字。
- 不擅自合并 A-15 和 A-015，也不把 A-4-1 当成 A-4；只提示「看起来相似」。

### 从标题取款号（按顺序，取到为止）
1. 标题末尾正好等于**已登记的款号**（支持任意符号组合，最准）。
2. 标题末尾符合「字母 + 数字」格式（沿用销售库存现有规则）。
3. 商家 SKU（排除纯数字、平台长编号）。
4. 用户手工绑定。手工绑定一旦存在，优先级最高。

匹配必须是完整款号：`A-1` 不能匹配到 `A-152`。标题和商家 SKU 不一致时，直播测试以**标题**为准，
同时进入「待确认」，不静默处理。销售库存已按商家 SKU 记账，不改历史，只提示。

### 一对多
- 一个款号 → 多个店铺商品（两家店、重复上架）：自动合并。
- 一个商品 → 多个款号（多规格各有 SKU）：按规格拆分销量；浏览、点击只有商品级，不重复累加，标注「多款共用」。
- 通用链接（直播间选款）：标记后不参与款号汇总。

## 数据流

选品采集 → 确定商品时填款号 → 商品库（款号档案）→ 上架标题带款号
→ 店铺商品 / 订单 / 库存 / 直播 / 广告按款号回流 → 爆款结论写回选品和商品库

## 各处改动（尽量不加新页面）

| 位置 | 改动 |
|---|---|
| 选品·确定商品 | 加「款号」列；按前缀自动取下一个号（A- → 现有最大号 +1），可改；重复时提示 |
| 选品·直播测试 | 按款号自动填订单、成交额等；手填保留，人工改过的不被覆盖 |
| 选品·爆款 | 显示款号；加入商品库时带上款号、图片、采集价和来源 |
| 商品库 | 加「款号」字段和搜索；卡片显示近 7 天销量、库存、爆款类型 |
| 商品详情 | 一块「这个款卖得怎么样」：两店销量、浏览→点击→加购→成交、库存可卖天数、利润 |
| 销售与库存 / 店铺商品分析 | 款号可点，跳到商品库；没有档案的一键建档（图片、标题自动带） |
| 出片 / 发布 / GMV Max | 通过款号找到店铺商品 ID，自动填现有 tiktokProductIds，不再手工绑 |
| 导入导出 | 支持你的表格：编号 / 图片 / 爆款类型，按 A、B、AA… 分表读取 |

## 爆款类型（对应表格里的大爆款、畅销款）

系统给**建议**，人工定的优先，不自动覆盖。判断用店铺真实数据：近 30 天销量名次、成交转化与店铺均值比、
是否持续多日出单。曝光不够的显示「测试中」，不下结论。具体门槛用你表格里已标记的款校准后再定。

## 数据怎么用起来

1. **上新闭环**：哪个关键词、平台、采集价位选出来的款最后卖得好。
2. **补货提醒**：爆款且库存可卖天数少 → 工作台提醒。
3. **跨店补位**：A 店好卖、B 店没上架的款 → 建议上架清单。
4. **素材优先级**：高转化但曝光少的款 → 优先出片；点击高不成交 → 查价格和主图。
5. **定价**：采集价、成本、售价、扣费后利润放在一起。

## 分阶段

1. **款号打通**：款号字段、匹配规则与测试、选品填款号、商品库档案、26 个旧商品迁移、待确认清单。
2. **款号看板**：商品详情数据、商品库销量和库存、爆款类型、跨店补位、表格导入导出。
3. **直播自动回填**：先用你的商家后台验证能否拿到「每场直播 × 每个商品」的数据；拿不到就支持导入直播商品报表。
4. **闭环分析**：关键词/来源命中率，并接入出片、GMV Max。

## 需要你定的

1. 款号是不是一款一号，不分颜色和尺寸？（默认：是；A-4-1 这类视为独立款）
2. 前缀含义：A/B/AA/C 耳环、D 项链、E 戒指？F、G、K 是什么？
   这决定自动编号按类目选哪个前缀；表格名是「耳环产品编号」但 D、E 是项链和戒指。
3. 删除或停用的号能不能重新用？（默认：不能）
