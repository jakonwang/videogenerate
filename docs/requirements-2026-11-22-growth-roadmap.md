## 一句话

把已有的「选品 → 素材 → 发布 → 投放数据」串成一个闭环，最后做成**自动驾驶模式**：系统每天自己跑，用户只做审批。

## 原则

- 先脊柱后做深：先把缺的那一环（批量发布）补上，再在闭环上叠功能。
- 少加入口：能放进已有页面的不新开页面；普通用户看到的默认流程一眼会用，策略参数收进「高级设置」。
- 网页/手机走服务器，桌面走本机；要电脑上账号的（Creatok、TikTok 后台 cookie）由电脑代办。
- 复用为主，下面每块都写了现有基础。

## 现有基础（盘点结果）

| 能力 | 已有模块 | 现状 |
|---|---|---|
| 选品 | `product-research`（飞瓜） | 可用 |
| 复刻 / 变体 | `clone`（`variantGenerator`、`aiScriptAnalyzer`）、`mix-studio`（`formulas`、`scriptWriter`、`insights`）、`dedupe` | 可用 |
| 审批收件箱 | `content-hub/reviewInbox` | 已有待审 → 通过/拒绝 → 学进品牌记忆 |
| 素材 ↔ 销量 | `content-hub/performance`、`content-hub/productSpine`、`mix-studio/insights` | 已能把成片对到 GMV MAX 素材，产出「下一条做什么」 |
| 投放 | `tiktok-gmv-max`（`profit`、`alertMonitor`、`creativeRotation`、`decisionEngine`…） | 已有利润护栏、疲劳素材告警、素材轮换 |
| 成本 | `dianxiaomi-inventory` | 商品成本 |
| 发布 | `tiktok-publisher`（Creatok）、手机分享发布 | 一次一条、一个号 |
| 配音 / 字幕 | `tts`（edge）、`subtitle` | 可用 |
| 直播切片 | `live-slicer` | 能切，不能自动发 |
| 编排 | `agent-os`（planner、stateMachine、capabilityRegistry） | 有骨架 |

**结论**：缺口最大的是「矩阵批量发布」，其余功能大多是在已有模块上加一层。

## 阶段 0：矩阵发布（脊柱，先做）

**用户看到**：发布中心多一个「账号」标签页 + 发布弹窗里能勾多个账号。
默认流程：选素材 → 勾账号/分组 → 一键发布（系统自动出变体、自动错峰）。

- 账号矩阵：账号、分组、平台、绑定的执行通道（Creatok / GeeLark 云手机 / 手机分享）、每日上限、状态（正常/掉线/养号中）。一号一环境。
- 批量排期：错峰时间窗、每号每日上限、新号养号期不发。
- 自动变体分发：同一素材给 N 个号时，用 `mix-studio` + `dedupe` 出 N 个版本，标题/封面/话题一起变。
- 任务队列：状态、自动重试、失败原因写成大白话。
- 执行适配器：先 Creatok（已有）+ 手机分享（已有）；GeeLark 放阶段 3。
- 发布记录写进云同步，网页/手机能看、能发起（要电脑的交电脑代办）。

**验收**：一条素材勾 10 个号，生成 10 个不重复版本，按时间窗逐条发出，任一失败能看到原因并重试。

## 阶段 1：快速见效（两块，基础都在）

### 1a 利润视角
**用户看到**：素材、账号、商品列表多一列「利润」，GMV 高但亏钱的标红。
- 复用 `tiktok-gmv-max/profit`（已有利润护栏）+ `dianxiaomi-inventory` 成本。
- 新做：把利润从「计划/商品」下钻到「单条素材」「单个账号」；退货率、佣金纳入。

### 1b 素材疲劳预警 + 自动补货
**用户看到**：GMV MAX 告警里「这条素材还能撑约 2 天，已备好 5 条新变体」，点一下送去审批。
- 复用 `alertMonitor`（已有疲劳告警）、`creativeRotation`、`clone/variantGenerator`、`reviewInbox`。
- 新做：衰退预测（剩余天数）、告警触发自动出变体、补位后自动换上（可关）。

## 阶段 2：多语言一键本地化

**用户看到**：成片页「出其他语言版」，勾越南语/泰语/印尼语/马来语/英语。
- 复用 `tts`、`subtitle`、`clone` 的 AI 文案能力、商品链接标题规则（`productLinkTitle`）。
- 新做：本地化文案改写（不是直译，按当地说法和卖点）、配音替换、字幕重排；口型同步作为可选高级项（看成本再定）。
- 计费：按语言/条扣点，走云端代理。

## 阶段 3：爆款基因库 + 多平台

### 3a 爆款基因库
**用户看到**：商品页/选品页「这个类目什么样的视频出单」，列出钩子类型、卖点顺序、节奏、配乐、字幕样式及各自转化。生成素材时默认套效果最好的结构。
- 复用 `clone/aiScriptAnalyzer`（拆结构）、`content-hub/performance`、`mix-studio/insights`（素材↔销量）。
- 新做：基因标签体系、按类目汇总、生成时注入。数据越多越准，是护城河。

### 3b GeeLark 云手机通道
- 按 `docs/requirements-2026-05-17-geelark-plugin-publish-closure.md` 实现，作为阶段 0 的一个执行适配器，覆盖 YouTube Shorts / Instagram Reels / Facebook 等。
- 云端执行，网页/手机可直接发起。

## 阶段 4：自动驾驶模式（主打，集大成）

**用户看到**：首页一个开关「自动驾驶」+ 「今日待批准」列表。每天 5 分钟点同意即可。

每日循环：
1. 选品：飞瓜涨势品 + 产品脊柱里的信号。
2. 生成：按基因库结构出一批素材和变体（含多语言）。
3. 审批：进 `reviewInbox`，用户批量通过。
4. 发布：矩阵错峰发布。
5. 复盘：次日拉 GMV MAX / 利润数据，好的继续出变体，差的停掉，疲劳的补货。

- 复用 `agent-os`（planner / stateMachine）串起前面所有阶段。
- 护栏：每日预算/点数上限、利润护栏、每号发布上限，任何一步超限就停下来等人。
- 默认只「建议 + 等审批」，全自动执行作为高级选项。

## 阶段 5：锦上添花

- **直播切片自动发**：`live-slicer` 切出高光 → 直接进矩阵发布。
- **竞品爆款雷达**：关注竞品店/达人，对方出爆款即推送，一键复刻。复用 `tiktok-creator-hub`、飞瓜。
- **AI 回复评论/私信**：带商品链接把评论流量转订单。需先确认平台接口与条款允许范围。

## 风险

- 平台条款：非官方自动操作（云手机、网页自动化）有封号风险，产品默认推荐合规通道并明确提示。
- 风控：同 IP / 同设备 / 同内容多号是封号主因，阶段 0 的「一号一环境」和自动变体不能省。
- 成本：多语言口型、批量生成会大量消耗点数，需先估算并在界面显示。
