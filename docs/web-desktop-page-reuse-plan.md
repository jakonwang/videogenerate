# 网页版直接复用电脑端页面：方案（2026-11-19）

## 一、要解决的问题

网页版有约 18 个页面是「照着电脑端重写的一份」（`apps/mobile/src/views/web/Web*.vue`，约 8000 行）。
电脑端改一个页面，网页版要再改一遍，容易漏、容易越改越不一样。

目标：这些页面在网页上**直接显示电脑端的页面**，以后界面只改一处。手机 App 自己的页面不动（屏幕不同，本来就该单独做）。

## 二、现在已经有的两条路

| 做法 | 已用在 | 怎么做的 |
|---|---|---|
| 网页替身 | 账号与会员 | 网页给电脑端页面提供一份同名的 `window.api.cloud`，里面调用云端接口（`lib/desktopCloudApi.ts`） |
| 电脑代办 / 服务器引擎 | GMV Max、达人中心、店小秘、发布中心、复刻 | 调用转给用户电脑（或服务器上每人一个子进程，跑电脑端同一套代码，复刻就是这样） |

## 三、方案：给每个模块写一个「网页替身」（推荐）

做法和「账号与会员」一样：网页版给电脑端页面提供一份 `window.api.<模块>`，方法名、参数、返回格式和电脑端一模一样，
内部调用网页现在已经在用的云端任务（生成、ffmpeg 处理、同步记录）。电脑端页面一行不改就能在网页上跑。

**为什么选这个，而不是把服务器引擎推广到所有模块：**

1. **手机 App 和网页数据还是同一份。** 现在网页和手机的图生视频、商品替换、上架助手记录都在云端同步集合里（`live-photo-items`、`replace-batches`、`listings`…），替身继续读写这些集合，手机不受影响。服务器引擎的数据在服务器本地数据库，每个模块都要再写一套同步桥，手机才看得到。
2. **省服务器资源。** 不用为每个用户常驻子进程；已有的 ffmpeg 排队、每日次数、扣点都继续生效（服务器引擎会绕过 W3 做的这些限制）。
3. **漏改会直接报错。** 替身按电脑端的接口类型写（`satisfies` 电脑端 `window.api` 的类型），电脑端加了方法、改了参数，网页版编译就过不去，不会悄悄不一致。

**换来的代价：** 电脑端模块的「接口」变了时，替身要跟着改一处（但页面不用改，且有编译报错提醒）。这比现在「整页重写一份」轻得多。

**电脑独有的操作在网页上的处理（已有的通用替身直接复用）：**

| 电脑端调用 | 网页上 |
|---|---|
| `pickFiles` / `getPathForFile`（选文件、拖文件） | 浏览器选文件 → 传到云端 → 返回云端文件引用 |
| `pickDir` / `saveFileAs` / 导出到文件夹 | 改成浏览器下载（多个文件打包 zip） |
| `shell.openPath` / `showItemInFolder` | 新标签页打开 |
| 本地路径的图片 / 视频（`localMediaUrl`） | 替身返回的就是云端链接，直接显示 |
| `on…` 进度事件 | 替身内部轮询云端任务，再按电脑端的事件格式推给页面 |

## 五、每个模块的做法（固定步骤）

1. 在 `apps/mobile/src/lib/desktopApi/<模块>.ts` 写替身，类型对齐电脑端 `window.api.<模块>`。
2. 网页路由改成 `desktopPage(() => import('@desktop-views/XxxView.vue'))`，手机 App 路由不动。
3. 对照验证：同一操作在电脑端和网页各做一遍（上传 → 生成 → 结果 → 下载 / 删除），截图对比；手机 App 能看到网页做出的结果。
4. 跑 `npm run typecheck`、`apps/mobile` 的 `npm run build:web`、相关云端测试。
5. 确认无误后删除旧的 `Web<模块>.vue`。

## 六、试点验收标准（商品替换）

- 网页打开商品替换，看到的就是电脑端页面（布局、文案、提示词版本抽屉、批次记录都一样）。
- 选商品、上传待替换图、出图、重试失败项、导出下载都能用；结果进审核收件箱和作品库。
- 手机 App 的商品替换能看到网页上做的批次。
- 电脑端 `productReplacement` 接口改一个参数，网页编译报错。

试点通过再做后面的模块；不顺利就停在试点，旧页面还在，不影响使用。

## 七、试点结果：商品替换（2026-11-19 完成）

网页 `/product-replace` 现在就是电脑端的 `ProductReplacementView`，旧的 `WebProductReplace.vue`（523 行）已删除。

**新增的通用底座（后面的模块直接用）**
- `apps/mobile/src/lib/desktopApi/`：每个模块一个网页版接口文件；`contract.ts` 引入电脑端 `PreloadApi` 类型，接口用 `satisfies DesktopApi['模块名']` 对齐（已验证：改错一个方法名，网页类型检查立即报错）。
- `DesktopPage` 支持第二个参数：页面专用接口只在页面打开期间替换 `window.api` 的对应部分，离开时还原；所有复用的电脑端页面都自带「从素材库选择」弹窗。
- 网页上传的文件统一用 `cloudfile:<fileId>/<名字>` 当路径；显示（`thumbnailUrl` / `vg://`）、打开（`shell.showItemInFolder` / `openPath`）都直接走云端链接。

**顺手修掉的已有问题**
- 电脑端：结果图点击「打开位置」调用了不存在的方法，点了没反应。
- 网页：选品接口先装了只有 `openExternal` 的 `shell`，导致所有复用页面「打开文件」都不可用。
- 网页：提示词「回滚」会把新版本覆盖成旧版本的名字和版本号（所有用提示词版本的网页工具都受影响）。
- 网页：全局拖放处理会挡住页面自己的拖放区。

**实测（本地云端 + 网页开发服务器）**：上传商品图、从商品库选商品、拖入场景图、从素材库 / 作品库选图、提交（本地没配 AI，正确显示「管理员还没有配置 AI 服务」）、批次记录（完成 / 失败 / 原因）、重试失败项（显示原因）、单张导出（下载并标「已导出」）、点结果新标签打开、提示词另存 / 启用 / 回滚；工作台、审核收件箱、会员、数据复盘照常打开；网页和电脑端类型检查、网页构建通过。

**和原网页版的差别**
- 商品参考图最多 4 张（电脑端页面写死 4 张；原网页版也是 4 张）。
- 「暂停 / 继续 / 取消」：云端生成提交后不能暂停，点了会提示；页面只在批次进行中显示暂停按钮。
- 批量导出是逐张下载（和原网页版一样），还没改成 zip。

**没验证到的**：真实 AI 出图（本地云端没有密钥），需要在配好 AI 的环境里跑一次。

## 七之二、视频批量水印（2026-11-19 完成）

网页 `/tools/watermark` 现在就是电脑端的 `VideoBatchWatermarkView`，旧的 `WebVideoWatermark.vue`（238 行）已删除。接口：`apps/mobile/src/lib/desktopApi/videoWatermark.ts`。

- 记录仍是 `video-tool-runs`（手机 App 同一份），按批次显示；进度由网页定时比对后推给页面（电脑端是主进程推送）。
- 文字水印和原网页版一样在浏览器里画成透明 PNG，预览即成片用图；图片水印上传后预览。
- 批次的「打开文件夹」在网页上是「下载这批成片」；「选择输出文件夹」提示网页版不需要。设置记在本浏览器。
- 接口类型检查发现电脑端 `videoWatermark.onChanged` 的取消订阅函数类型写错（返回了 IpcRenderer），已改正。
- **修了服务器水印的大小问题**（网页和手机原来都受影响）：服务器自带的 ffmpeg 里 `scale2ref` 的变量是反的，水印按「水印图宽度 × 比例」算宽、按画面比例算高，文字水印变得又大又竖着拉长。现在先量视频宽度和水印图尺寸，再直接缩放。实测 360×640 视频、22%、左上 4%：水印 79×16 落在 (14,14)，和预览一致。
- 实测：上传视频、文字水印预览、提交并在服务器跑完（进度自动刷新）、下载整批、图片水印上传与预览、选择输出文件夹的提示、删除批次；`test:cloud-video-tools` 通过。

## 七之四、链接下载（2026-11-19 完成）

网页 `/tools/download` 现在就是电脑端的 `VideoParserDownloadView`，旧的 `WebLinkDownload.vue`（211 行）已删除。接口：`apps/mobile/src/lib/desktopApi/videoParserDownload.ts`。

- 记录仍是 `video-tool-runs`（kind = parse-link，手机同一份），同一链接不重复下载；每行自动取出链接，没有链接的行算失败，一次最多 50 条。
- 页面检查「有没有 TikHub 密钥」：网页上由平台提供，直接放行；没开通时提交会显示云端的原因（「管理员还没有配置 TikHub 密钥…」）。

- **页面样式归位**：这个页面的版式原来写在电脑端 20000 行的全局 `styles.css` 里，选择器限定 `.app-shell`，网页不加载、也匹配不上，网页上排版是乱的。已把这一整块（296 行，只针对本页）移到 `design-system/video-parser-download.css`，由页面自己引入，选择器改成 `:is(.app-shell, .web-shell)`（优先级不变）。电脑端构建确认样式随页面打包；**还没在电脑端软件里看过**。
- 顺手补全：网页版的账号状态替身缺 `ensureLoaded / enforced / licensed / hasFeature`（这个页面一打开就报错）；`DesktopPage` 的接口合并改成「找不到再去原对象找」，不会把电脑代办的方法丢掉。
- 实测：页面版式和电脑端一致；提交链接（本地没配 TikHub，显示原因）；已下载视频卡片（状态、作者、已使用、失败原因、封面）、预览播放、「打开文件」下载、重试失败项（显示原因）、删除。

**后面模块要注意**：电脑端很多页面的版式也写在全局 `styles.css` 里（`#app .app-shell …`），迁移时要先查，把该页专用的那块移到 `design-system/<页面>.css` 由页面引入。

## 七之五、批量字幕：暂缓（2026-11-19 决定）

电脑端「批量字幕」不走 `window.api`，而是调用电脑上的本地 Web 服务（`webApiClient` → `src/main/modules/web-platform`，约 3300 行），预览和成片用 Remotion（无界面浏览器）渲染；云端只有简化版字幕任务（识别口播字幕 + 标题图叠加），电脑端页面的大部分选项（字幕模板、字体、标题池与策略、服务器渲染的预览帧、叠加图）在云端没有对应能力。决定：**先跳过**，网页保留现在的 `WebBatchSubtitle.vue`，其余模块做完后再定（可选方案：服务器跑电脑端字幕引擎，约 3–5 天、服务器开销明显更大）。

## 九、图生视频 + 批量字幕：服务器跑电脑端引擎（方案，2026-11-19）

### A 期：图生视频（约 3 天）

  - 改某一条视频的标题会把统一标题也改掉——已修。
  - 刚载入任务就显示「有未保存的修改」——已修。
  - 「已暂停」状态之前显示成「草稿」——已修。
- 实测：网页宽屏 / 手机宽度、电脑端构建版都正常，网页上快速预览出图正常，无页面报错。

## 十四、分页 + 遗留问题收尾（2026-11-19）

- **视频解析下载分页**：视频库从「显示更多」改为分页（复用图生图素材的 `MaterialPager`），每页 24 / 48 / 96 条，记住上次选择；筛选、搜索、排序后回到第 1 页；「全选」只选本页。电脑端 60 条测试数据实测：3 页 → 翻页 → 改 48 条 / 页变 2 页。
- **上架助手导出的越南文属性名**：店小秘导出的默认商品属性里，越南文从第一次提交起就被存成了「?」（如 `S? l??ng tr?n m?i g?i`）。已按残留字母还原 28 处（如「Số lượng trên mỗi gói」「Phụ kiện cặp đôi」「Kim cương giả」）；用户已保存的配置读取时按属性 / 取值 id 自动修正，用户自己加的不动。**两处请核对**：耳饰「Dịp」的取值还原为「Điềm lành」、材质还原为「Phủ kim loại」，这两个从残留字母看有别的可能，以 TikTok 越南站后台为准。
- **TikHub 代理收紧**：云端 TikHub 代理原来放行任意接口，登录用户可以用平台的 TikHub 账户调任何付费接口、查账户信息（`/api/v1/tikhub/user/*`）。现在只放行视频解析用到的 8 个 GET 接口（列表和解析共用 `TIKHUB_PARSE_PATHS`），其它一律拒绝。`test:cloud-ai-proxy` 已补对应检查。
- **网页批量渲染不再干等**：网页上「开始批量渲染 / 继续」几秒内没做完就先返回「处理中」，提示可以离开页面，进度在底部渲染栏和「任务」里看；服务器继续渲染（引擎并行处理请求，查进度不会被渲染卡住）。电脑端不变。
- **仍需要外部条件才能验证**：6 个新平台的真实 TikHub 返回（需要 TikHub 密钥）、图生视频的真实 AI、Linux 服务器上实际渲染一次。

## 十五、批量字幕：改成水印页同款 + 预览卡顿崩溃（2026-11-19）

**卡顿 / 崩溃的原因**：以前每改一次样式、每切一条视频，0.9 秒后就让后台用 Remotion 渲染一张预览（每次起一个无界面 Chrome），上一张没出来就再排一张。电脑端这些都在软件进程里跑，连着拖几下滑块就把软件拖垮。

**现在**：
- 页面上的预览是**实时画出来的**（SVG 叠在视频画面上），改字、换模板、拖滑块立刻变，不占机器、不请求服务器（实测：拖 6 次滑块 + 换模板，零次渲染请求）。
- 实时预览和成片用**同一套排版**（新文件 `src/shared/subtitleTitleLayout.ts`：分行、字号、位置），成片渲染（`batchSubtitleBitmap.ts`）也改用它，所见即所得。
- 「生成真实画面 / 生成预览视频」改为手动点；并改用和成片相同的渲染（SVG 叠图 + ffmpeg），不再起 Chrome；只要画面时不做预览视频。实测网页上真实画面和实时预览分行一致。
- 「最大行数」以前渲染时根本没用上；现在标题超过最大行数会自动缩小字号（最多到 60%），页面上会提示缩到了多少。
- 预览文件以前每次都新建目录、越堆越多，且目录名用整段来源 id，Windows 上路径超长导致生成失败；现在用短哈希目录、每个视频只留最新一次。

**界面（和视频批量水印同一套）**：左边 1 选择视频（素材库 / 电脑 / 成片库，可拖入；每条视频后面直接填单独标题，没标题的标黄）→ 2 标题内容（统一 / 随机标题池；新增「AI 帮我写标题」，填产品和卖点，选越南语 / 英语 / 中文，生成 10 条进标题池）→ 3 标题样式（模板卡片带效果样字、字体下拉、颜色、滑块、位置 / 对齐 / 最大行数）→ 4 开始处理；右边效果预览 + 处理记录（每次开始都是一条新记录，不再覆盖上一次；可暂停 / 继续 / 重试失败 / 打开文件夹 / 套用这条的标题和样式）。标题和样式记在本机，下次打开还在。
- **顺带**：视频批量水印的效果预览改为叠在第一个选中视频的画面上（以前是空白渐变底）。
- **还没做**：批量字幕没有「选择输出文件夹」「完成后存入素材库」（后台目前不支持，要另做）。
- 实测：网页（选视频、实时预览、换模板、生成真实画面、开始处理并出现在记录里）和电脑端构建版均正常、无报错；`test:batch-subtitle-bitmap`、`test:batch-subtitle-ass`、`test:cloud-clone-engine` 通过。

## 十六、照着投放效果好的视频改批量字幕（2026-11-19）

分析了 5 条效果好的饰品带货视频（7~19 秒、9:16）的字幕，共同点：
1. 标题很短，3~8 个词，口语、像跟朋友说话（「Đeo ngược vẫn đẹp lun nha mấy bà」「Basic sang tai」），最多两行；
2. 结尾一个表情（✨🤩😚🔥）；
3. 白色、中等粗细的小字（约画面高度 3~4%），不描边，只有很淡的阴影，像在 TikTok 里直接打的字；
4. 放在商品旁边（画面高度 23%~58% 不等），不是固定贴顶 / 贴底；两行时一样大、块内左对齐；
5. 整条视频同一句（我们已支持）。

**发现并修好的不足**：
- **表情在成片里画不出来**：成片用字体文件画字形，文字字体里没有表情，以前会是空白 / 方块。现在表情用 Twemoji 图片画（首次联网下载后缓存）。实测越南文 + ✨ / 😚 正常。
- **字重一直没生效**：成片字体只有常规体，以前「900 粗体」只是预览里的效果，成片都是细字。现在用同色描边模拟加粗，新增「粗细：常规 / 中粗 / 粗 / 特粗」，预览和成片一致。
- **阴影模糊没生效**：成片阴影以前是不模糊的硬影；现在按「阴影模糊」做柔和阴影，预览同样画法。
- **位置只能顶 / 中 / 底**：新增「自定义」位置（上下、左右两个滑块），也可以**直接在预览画面上拖动标题**；左右自定义时整块放在指定位置、块内按对齐方式排。
- **第二行固定变小字**：新增「各行一样大」开关。
- **新模板「TikTok 原生」**（放第一个，新用户默认）：白色中粗 52 号、不描边、柔和阴影、两行一样大、放在画面 42% 处。旧模板保留，点旧模板会恢复大标题样式。
- **常用表情按钮**：标题框下一排 ✨🔥🤩😍🥰😚💖👇💯🎁，插到光标处；随机标题池没点进输入框时给每条末尾都加。标题区顶部加了一句写法提示。
- **每条视频位置随机微调**（开关，约 ±4%）：同一批发出去画面不完全一样；按视频 id 算，同一条每次一致。
- **AI 写标题**：以前选越南语也会出中文（后台只认 en-US）；现在按所选语言生成，写法按上面的规律（短句、口语、结尾一个表情、不带标签和价格），并用这几条视频的标题当例子。**未实测真实 AI 输出**（本机没配 AI 密钥）。
- 渲染缓存版本号升到 4，旧的叠加图不会被复用。
- 实测：成片（服务器渲染）和页面实时预览位置、分行、表情一致；网页上拖动摆位、加表情、换模板正常；电脑端构建、`test:batch-subtitle-bitmap`、`test:batch-subtitle-ass`、`test:cloud-clone-engine` 通过。

## 十七、成片表情显示成方块（2026-11-19）

- 用户反馈：成片里「6666666 ✨✨」的表情变成带叉的方块。方块是 Noto Sans 的「缺字」字形，说明跑的还是改之前的渲染代码（用文字字体画表情）。`npm run dev` 不会在后台代码改动后自动重启主进程，页面会热更新但渲染还是旧的——**改完后台代码要关掉重开软件**。
- 另一个隐患：新代码的表情图片从 jsDelivr 下载，国内网络可能连不上，表情会直接消失。现在随软件带 101 个常用表情的 Twemoji 图片（`resources/fonts/emoji`，332 KB，CC-BY 4.0，见目录里的 README），先用本地的，没有再联网下载；构建时随字体一起复制（`scripts/copy-font-resources.mjs`），服务器引擎从 `CLOUD_FONTS_DIR/emoji` 找到。
- 新测试 `npm run test:batch-subtitle-emoji`：断网情况下渲染一条非 9:16 的视频，标题「6666666 ✨😚」，断言两个表情都画成图片；实际出帧表情正常。

## 十八、各模块「批量添加字幕」和批量字幕页面统一（2026-11-19）

复刻（任务列表）、图生视频（库 / 导出）、tk创意室里的「批量添加字幕」弹窗以前各自复制了一份旧版界面（3 个旧模板、数字输入框，没有粗细 / 表情 / 自定义位置 / 预览）。现在全部换成同一个组件，和「视频批量字幕」页面同一套：

- `lib/subtitleStyle.ts`：默认样式（TikTok 原生）、6 个模板、字体 / 表情列表、记住的设置（各处共用同一份，一处改了另一处打开就是同样的标题和样式）。
- `ui/components/subtitle/`：`SubtitleTitleFields`（统一标题 / 随机标题池、写法提示、表情、AI 写标题）、`SubtitleStyleFields`（模板、粗细、颜色、位置含自定义、对齐、行数、各行一样大、位置微调）、`SubtitleLivePreview`（实时预览，可拖动摆位，和成片同一套排版和画法）、`SubtitleStudioDialog`（弹窗：左边标题 + 样式，右边用第一条视频的封面实时预览；单条时保留各模块自己的「撤销字幕」按钮）。
- 「视频批量字幕」页面也改用这几个组件（页面从约 2300 行减到约 1400 行）。
- 三个模块的提交逻辑不变（各自把字幕版本挂回复刻项目 / 图生视频条目 / tk 镜头），只是标题和样式从新弹窗来；新样式字段（粗细、自定义位置、各行一样大、位置微调）会一路带到渲染。
- 实测：网页上图生视频「字幕」弹窗打开、沿用批量字幕页面的标题和模板、提交后「已为 1 个视频生成字幕」，条目显示已加字幕；电脑端构建版打开复刻、tk创意室、图生视频、批量字幕页面无报错（复刻和 tk创意室没有现成数据，弹窗本身没在电脑端点开过，组件和图生视频是同一个）。
